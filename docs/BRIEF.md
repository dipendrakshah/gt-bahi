# Bahi — one-page brief

**Date:** 18 September 2026  
**Working name:** Bahi (बही)

## Problem

Nepali multi-channel sellers capture orders in DMs and sites, take money on Fonepay/eSewa/COD, and reconstruct VAT in Tally weeks later. Stock, cash, and IRD are three different novels.

## Product

Order-to-VAT system of record. A sale becomes reserved stock, matched payment, and an immutable tax invoice. API + MCP expose that record. Storefront widget and chat are clients, not the company.

## Not

Shopify clone. Tally skin. Meta chatbot. MCP wrapper.

## Who

D2C / brand operators, VAT-registered, web + social, ~NPR 2–20M/month GMV. CAs as channel.

## Model

NPR 2k–8k/month tiers. Capped matcher attach. Implementation. CA seats. Planning ARPU NPR 6,000/month.

## Economics

Lean burn NPR 1.0–1.6M/month. Break-even ~170–270 paying orgs. Base case 24–36 months (late 2028 / FY 2085). Twelve months only with existing distribution.

Eight design-partner conversations. P0 invoice-from-order. Do not start a theme engine.
